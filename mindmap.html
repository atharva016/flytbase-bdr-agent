Input Layer

Campaign Brief Ingestion
Input: Target Vertical (Latin American mining), Reference Account (SQM), Target Roles (Head of Ops, VP HSE, Site Directors), FlytBase Angle (drone inspection replacing contracted crews).

The system accepts a structured JSON brief. The SQM profile is used as the "anchor" to model the Ideal Customer Profile (ICP) — matching on scale, geography, commodities, and operational complexity.
Architecture Decision
Single Agent vs. Multi-Agent Pipeline?
Decision: Multi-agent pipeline with 4 specialized sub-agents.

Why not single agent? A single monolithic prompt would produce shallow, hallucination-prone output. Each stage requires different skills: web search for discovery, strategic analysis for research, creative writing for emails.

Why 4 agents? Maps directly to the BDR workflow: (1) Find companies → (2) Find people → (3) Research deeply → (4) Write outreach. Each agent is independently testable, debuggable, and improvable.
Stage 1 — Account Identification
Agent 1: Account Finder
Find Mining Companies Matching SQM Profile
How it works:
1. Fires 8 parallel DuckDuckGo web searches targeting Latin American mining companies
2. Gathers 40+ real search results (titles, snippets, source URLs)
3. Feeds search context + SQM ICP profile to Gemini 2.0 Flash
4. LLM identifies 8-12 real companies with ICP match reasoning

ICP Matching Criteria: Revenue scale (US$1B+), geography (LatAm), commodities (lithium/copper/iron ore), operational complexity (open-pit/underground), contracted crew dependency, hazardous site characteristics.

Output: Structured JSON with company name, country, commodities, revenue, key sites, ICP match score (0-100), and reasoning.
Quality Gate
Are accounts real and verifiable?
Each account is cross-referenced against web search results. The LLM is instructed to only include companies with verifiable public data. If fewer than 5 accounts pass validation, the search queries are broadened and the stage is re-run.
pass / fail
Fail Path
Insufficient Accounts
If web search returns limited results (e.g., rate limiting, connectivity issues), the system logs the failure, shows partial results, and explains what went wrong. Fix: Add fallback to pre-seeded ICP database or switch search provider (SerpAPI, Tavily).
Pass Path
8-12 Verified Accounts
Accounts like Codelco, Antofagasta Minerals, Vale, Southern Copper, BHP Escondida, Collahuasi, Cerro Verde, Albemarle Chile, CAP Minería, Arcadium/Rio Tinto Lithium, ENAMI, Mineração Usiminas — all real companies with verifiable profiles. Each includes ICP match score and specific reasoning.
Stage 2 — Contact Discovery
Agent 2: Contact Hunter
Find Decision-Makers at Each Company
How it works:
1. For each company, runs 4 targeted web searches (LinkedIn + company leadership)
2. Searches for: "[Company] Head of Operations", "[Company] VP HSE", "[Company] Site Director mining"
3. Collects up to 60 search results with LinkedIn profiles and news mentions
4. LLM identifies 2-3 contacts per company, prioritizing by role relevance

Target Roles: Head of Ops → VP HSE → Site Director → COO → VP Innovation

Output: Name, title, seniority, company, LinkedIn URL, email (where publicly available), relevance explanation.
Honest handling: If a contact can't be verified, it's marked "Contact research needed" — no invented personas.
Stage 3 — Account Research
Agent 3: Research Analyst
Deep Intelligence Briefs per Company
How it works:
1. For each company, runs 6 deep research queries (news, tech, safety, expansion, financials, contractor usage)
2. Gathers 10+ sources per company (news articles, press releases, annual reports)
3. LLM synthesizes into structured research briefs

Research Dimensions:
• Recent News: Expansions, investments, leadership changes (last 12-24 months)
• Tech Signals: Automation, AI, digital transformation, existing drone programs
• Safety/ESG: Incidents, sustainability goals, environmental commitments
• FlytBase Angle: Specific pain points where autonomous drone inspection solves real problems (blast zone clearance, conveyor monitoring, tailing dam integrity, stockpile volumetrics, perimeter security)

All data is real. Sources are cited. Fabricated data = disqualification.
Stage 4 — Email Generation
Agent 4: Email Composer
Hyper-Personalized Outbound Emails
How it works:
1. Merges each contact with their company's research brief
2. LLM generates unique email for each contact using specific research hooks
3. Each email references real company events, not generic industry messaging

Email Rules:
• Specific to contact's company AND role — not {first_name} templates
• Opens with a real hook (recent expansion, tech investment, safety initiative)
• References FlytBase proof points: Anglo American at Quellaveco (Peru), Shell offshore, CSX rail
• 4-6 sentences max — BDRs don't write essays
• Clear CTA: 15-minute discovery call
• Signed by: Atharva Jamdar, BDR, FlytBase
Final Output
Dashboard: Accounts + Contacts + Research + Emails
All results displayed in a live, interactive web dashboard with 4 tabs:
• Accounts: Company cards with ICP scores and match reasoning
• Contacts: Sortable table with names, roles, LinkedIn links
• Research: Expandable intelligence briefs per company
• Emails: Preview cards with copy-to-clipboard functionality

Results also saved as JSON for export. An Account Executive can pick this up and know exactly what to do next.

Architecture & Design Decisions
Why This Stack
Python + Flask: Fast to build, excellent AI library ecosystem.
Gemini 2.0 Flash: Fast inference, free tier, strong at structured JSON output.
DuckDuckGo Search: No API key required, no rate limiting, real-time web data.
SSE Streaming: Real-time pipeline progress to the frontend — users see each stage complete live.
No Clay/Apollo/etc.: Built from scratch to demonstrate engineering capability, not tool assembly.
Edge Cases & Failure Handling
LLM returns invalid JSON: Fallback parser extracts JSON from markdown code blocks.
Web search rate-limited: Graceful degradation — uses cached results + fewer queries.
Contact not found: Marked honestly as "Contact research needed" — never fabricated.
Gemini API down: Error surfaced to user with clear explanation.
Duplicate companies: Deduplicated by company name normalization.
What I'd Improve with More Time
Multi-LLM fallback: Chain Gemini → Claude → GPT-4o for redundancy.
LinkedIn API integration: Verified contact data vs. web scraping.
Email A/B variants: Generate 2-3 email variants per contact for testing.
CRM integration: Direct push to Salesforce/HubSpot with lead scoring.
Scheduling agent: Auto-schedule follow-up sequences.
Feedback loop: Track email opens/replies to improve personalization model.
